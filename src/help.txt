Run commands and Nushell code. Every call is a fresh Nushell with nux's own commands.

RUN SOMETHING
  Code on stdin, in a quoted heredoc (nothing needs escaping), with -r: why, in a few words.
      nux -r 'find the large files' <<'NU'
      ls **/*
      | where size > 1mb
      | select name size
      NU
  One line without single quotes of its own: nux <<< 'git status'. There is no -c.
  It runs in the directory you call nux from.

WRITE IT AS A SCRIPT
  Long flags (--context 2, not -C 2). A pipeline with a closure or over 4 steps: one step
  per line, starting with `|`. if/else/for/loop blocks always over several lines. Errors
  name their line, so this names the step. A short pipeline stays on one line.
      ls **/*
      | where type == file
      | each {|file| {name: $file.name, mb: ($file.size / 1mb)} }
      | sort-by mb --reverse

WHAT YOU GET BACK
  Every statement's value, in order; with several, each under `── line N: <code>`.
  let, def, use, for, print and cd give none; `| ignore` drops one.
    table    Markdown (header every 20 rows); wide or nested: `12 rows`, `## 0`, `## 1`, ...
    record   `key: value` lines
    list of texts  `12 items`, one per line
    text     as is; inside a table, record or list in "..." (JSON escapes) when it could
             be misread: empty, padded, a number, true/false/null, a newline
    durations, sizes  `~1min 28sec`, `~4.512MB` (~: rounded)
    other    NUON. Exact types: `| to nuon`; JSON: `| to json --raw`; NUX_FORMAT=nuon: all
  An external command: its output, a value to pipe on as it is: ^git log --format=%h |
  lines. When it fails: all of it, "exited with code N", and the call stops. `| complete`
  ({stdout, stderr, exit_code}) only to read stderr or the exit code, or to go on after a
  failure; never `| complete | get stdout`. stderr is marked `stderr (cmd): ...`;
  `e> /dev/null` silences it, `e>| lines` pipes it on. Inside a loop, closure or def, a
  failure ends the call without its output: `^cmd | complete | check-exit "cmd"`.
  `| show` (or `| show { length }`) prints a value on the way and passes it on.
  No time limit of its own: give your tool call more time for a long build or install.

NOTHING CARRIES OVER, EXCEPT WHAT IS KEPT
  Variables, defs and cd end with the call: do in one call what belongs together.
      kept                          what is kept: name, size, kept
      kept result-3 | first 20      a result too large to print (over 10 KiB)
      let big = (kept big)          a variable of a call that FAILED
      $rows | kept --save rows      keep a value yourself; later: kept rows
  Per agent conversation, in {kept_dir}.

YOUR OWN COMMANDS
  ~/.config/nux/prelude.nu runs at the start of every call. Modules: `use home/tools`
  (~/.config/nux/tools.nu), `use project/checks` (.nu/checks.nu at the git root); inside
  them, use each other by those names, not by a relative path.
  try-nu 'code' runs code apart, giving {value, error, printed, stderr}: nux help try-nu

COMMANDS THAT GIVE TABLES   (examples for each: nux help <command>)
      search 'pattern' src --glob '*.ts'    file contents (ripgrep): file, line, text.
                                            .gitignored files left out (--all: in);
                                            --context 3, --only-matching, --files
      search 'pattern' --context 2 | to grep
                                            rows as grep prints them, to read
      ast-find --lang ts 'console.log($$$A)' src
                                            code by structure (ast-grep); with --rewrite
                                            '...', then | ast-apply: a change in many files.
                                            Only what the pattern names is replaced: the `;`
                                            after `return $X` stays (column `trailing`)
      git log --since "1 week ago"          commits: hash, short, date, author, subject
                                            (--files, --body, --oneline, --range main..HEAD)
      git status                            changed files: path, staged, unstaged
      git diff                              per file: path, added, deleted (--staged, a
                                            path, HEAD~1 HEAD, main...HEAD); --lines: per
                                            line

                                            to READ a diff: the hunks of the rows piped in
      git info                              root, branch, head, upstream, ahead, behind, ...
      git show-file HEAD~3 src/a.ts         a file's text at a commit (paths from here)
      git status | where ... | git add      stage the rows; gives git status after
  `git` is only these; anything else (`git commit`, `git push`) is an error: git
  itself is `^git commit -m "..."`. pnpm, docker and the rest work as in any shell.
      ^pnpm typecheck | complete | from tsc
                                            TypeScript errors: file, line, column, code,

                                            Package script: with-env {NODE_OPTIONS:
                                            "--test-reporter=tap"} { ^pnpm test

      edit-file <path> <old> <new>          replace text found exactly once (a table of
                                            old/new: several edits, all or nothing)

      ^pnpm outdated --format json | complete | get stdout | from json   (exits 1 if any)
      open package.json | get scripts       (also yaml, toml, csv, xlsx, sqlite as data)
      open orders.csv | into float amount   csv/tsv values are text as written ("02134")
                                            into float/int 1,500.25, into float-eu 1.500,25
      http get <url>                        (JSON already parsed; --raw for text)
      http get --full --allow-errors <url> | get status    (not curl -w "%{http_code}";
                                            redirects: --redirect-mode manual)

NUSHELL FIRST, THEN PY OR JS
  Text: `parse --regex '(?<key>\w+)=(?<value>\S+)'`, str replace -r, split row. State
  across rows: `mut` and a `for` loop (a closure cannot change a `mut`).
  For a library Nushell lacks, `py` and `js` run code on the input as `data`, values keep
  their types: ls | js --with {limit: 1kb} 'data.filter((f) => f.size.bytes > limit.bytes)'
  Details: nux help py, nux help js

FROM BASH
      mkdir -p a/b                  mkdir a/b
      rm -rf dir                    rm -r dir
      cat file                      open --raw file    (without --raw: json, yaml as data)
      cat notes.md                  open --raw notes.md (without --raw: a table of elements)
      grep pat file                 search pat file    (a value: where $it =~ pat)
      sed 's/a/b/'                  str replace a b    (-r: a regex, -a: every match)
      for f in *.md; do ...         for f in (glob *.md) { ... }
      $(cmd)                        (cmd)              (...(cmd) spreads a list as args)
      echo $PATH                    $env.PATH
      export FOO=bar                $env.FOO = "bar"
      FOO=bar ./bin                 FOO=bar ./bin, or with-env {FOO: bar} { ./bin }
      type foo                      which foo
      cmd1 && cmd2                  cmd1; cmd2         (a failing command ends the call)
      cmd1 || cmd2                  try { cmd1 } catch { cmd2 }
      cmd > file                    cmd o> file        (a value: ... | save file)
      cmd >> file                   cmd o>> file
      cmd 2>&1 | next               cmd o+e>| next     (there is no 2>&1)
      cmd > /dev/null 2>&1          cmd o+e>| ignore
      cmd | tee log | other         cmd | tee { save log } | other
      a long \ line                 wrap it in ( ... ), or one step per line starting with |

LOOK THINGS UP   (Nushell changes between versions; check before guessing)
      nux find <word>               commands whose name or description mentions it
      nux help <command>            usage, flags and examples: nux help str replace

GOOD TO KNOW
  - No terminal, and no stdin unless you pipe a value in: nothing interactive. A server
    does not belong in a call: start it in the background (Claude Code:
    run_in_background), then, in a call, timeout 1min { wait-for url ... }.
  - '...' and r#'...'# have no escapes; "..." has \n \t \" \\ \u{1b}. A value in text:
    $"hello ($name)"; "hello $name" stays as written. In $"..." every ( ) runs as code:
    \( \) for text. A regex goes in '...'. A ' in text: "it's" or r#'it's'#. A commit
    message: always a raw string, r#'Fix the footer (see notes)'# | ^git commit -F -.
    Colors out of text: ansi strip.
  - A flag with a value from a variable is one string: ^mysql $"--password=($pw)" db.
    External commands see $env.X and with-env, not `let` variables.
  - A hash like 91778bb as a bare word is a size or a command: quote it, "91778bb".
  - `where name =~ 'x'` fails on a null name: `where name != null and name =~ 'x'`.
  - `glob **/*.ts --no-dir | path relative-to (pwd)`: files only, from here (glob has
    hidden files and .git; ls **/* has not). glob '{src,test}/**/*.ts' --exclude
    [**/target/**]. `find` filters a value, not files.
  - Text in columns, as a table: ^ps -o pid,comm | detect columns (--guess for ^df -h).
  - `http post -t application/json <url> {key: value}`: the whole MIME type.
  - `job spawn { ... }` lasts until the call ends; `job send 0` there, `job recv` here.
